01ภาพรวม

ให้สร้าง REST API สำหรับห้องสมุดเล็ก ๆ ที่ทำสิ่งเหล่านี้ได้

  • จัดการสมาชิก ได้แก่ สมัคร ดูข้อมูล และระงับ/เปิดใช้งาน
  • จัดการหนังสือ และเล่มจริง (copy) โดยหนังสือ 1 เรื่องมีได้หลายเล่ม
  • ยืม ต่ออายุ และคืนหนังสือตามกฎทางธุรกิจ
  • คำนวณค่าปรับเมื่อคืนช้า และให้ชำระค่าปรับได้

โจทย์นี้ไม่ได้วัดที่ CRUD แต่วัดสามเรื่องนี้

แยก layer ให้ขาดcore ไม่รู้จัก HTTP และ database เลย
เวลาต้องเทสต์ได้ห้ามเรียก time.Now() ใน core ให้ inject Clock เข้ามาแทน
กันการยืมซ้อนใช้ transaction ให้เล่มเดียวกันถูกยืมพร้อมกันสองคนไม่ได้

วิธีอ่านสัญลักษณ์ (Crow's Foot)

สัญลักษณ์ที่ปลายเส้นบอกว่า ตารางฝั่งตรงข้ามหนึ่งแถว เชื่อมกับตารางฝั่งนี้ได้กี่แถว แต่ละปลายมีสองส่วน ส่วนที่ชิดกล่องบอกจำนวนสูงสุด ส่วนที่ถัดออกมาบอกจำนวนต่ำสุด

| ขีด = 1 ○ วงกลม = 0 (ไม่มีก็ได้) < สามแฉก (ตีนกา) = หลายแถว

กล่องสีเทาในรูปคือตาราง ตามมาตรฐานวงกลมควรเป็นวงกลวง ถ้าเห็นเป็นวงทึบในธีมมืดความหมายก็เหมือนเดิม

ความสัมพันธ์ในโจทย์นี้

ความสัมพันธ์อ่านว่า
MEMBERS ||--o{ LOANSสมาชิก 1 คนมี loan ได้ตั้งแต่ 0 ถึงหลายรายการ ส่วน loan 1 รายการต้องเป็นของสมาชิก 1 คนพอดี
MEMBERS ||--o{ FINESสมาชิก 1 คนมีค่าปรับได้ตั้งแต่ 0 ถึงหลายรายการ ส่วนค่าปรับ 1 รายการเป็นของสมาชิก 1 คนพอดี
BOOKS ||--o{ BOOK_COPIESหนังสือ 1 เรื่องมีเล่มจริงได้ตั้งแต่ 0 เล่มขึ้นไป ส่วนเล่มจริง 1 เล่มเป็นของหนังสือ 1 เรื่องพอดี
BOOK_COPIES ||--o{ LOANSเล่มจริง 1 เล่มถูกยืมได้หลายครั้งในต่างช่วงเวลา แต่ในช่วงเวลาหนึ่งต้องมี loan ที่ยังไม่คืนได้แค่ 1 รายการ
LOANS ||--o| FINESloan 1 รายการมีค่าปรับได้ไม่เกิน 1 รายการ ถ้าคืนตรงเวลาจะไม่มีค่าปรับ

ตัวย่อในกล่องตาราง: PK คือ primary key, FK คือ foreign key ที่ชี้ไปตารางอื่น และ UK คือ unique key ที่ห้ามมีค่าซ้ำ

  • เงินเก็บเป็น integer (int64) ห้ามใช้ float
  • สถานะของ loan (ACTIVE / OVERDUE / RETURNED) ไม่ต้องเก็บใน DB ให้คำนวณจาก returned_at, due_at และเวลาปัจจุบัน
  • กำหนดคืนนับเป็นวัน ไม่นับเวลา ใช้วันตามปฏิทินของ Asia/Bangkok (UTC+7) ถ้าครบกำหนดวันที่ 15 จะคืนกี่โมงของวันที่ 15 ก็ไม่ถือว่าเกินกำหนด เก็บ due_at เป็น 23:59:59 +07:00 ของวันครบกำหนด และเช็คการเกินกำหนดด้วย date(now) > date(due_at)
  • ถ้าใช้ Postgres ควรมี UNIQUE (copy_id) WHERE returned_at IS NULL เป็นด่านสุดท้ายกันการยืมซ้อน

03กฎทางธุรกิจ

3.1 การยืม (Borrow)

ให้ตรวจตามลำดับในตาราง และคืน error ของข้อแรกที่ไม่ผ่าน ลำดับต้องแน่นอนเพื่อให้เทสต์ได้

#เงื่อนไขError ถ้าไม่ผ่าน
1มีสมาชิกคนนี้อยู่MEMBER_NOT_FOUND
2สมาชิกมีสถานะ ACTIVEMEMBER_SUSPENDED
3สมาชิกไม่มีค่าปรับค้างชำระHAS_UNPAID_FINES
4สมาชิกไม่มี loan ที่เกินกำหนดแล้วยังไม่คืนHAS_OVERDUE_LOANS
5สมาชิกยืมค้างอยู่น้อยกว่า 3 เล่มLOAN_LIMIT_REACHED
6มีเล่มตาม barcode ที่ส่งมาCOPY_NOT_FOUND
7เล่มนั้นมีสถานะ AVAILABLECOPY_NOT_AVAILABLE

ถ้าผ่านครบทุกข้อ ให้สร้าง loan โดย borrowed_at = now และ due_at = สิ้นวันของ (date(now) + 14 วัน) (ยืมวันที่ 1 กี่โมงก็ได้ จะครบกำหนดวันที่ 15 เวลา 23:59:59) แล้วเปลี่ยน copy เป็น BORROWED ทั้งสองขั้นตอนต้องอยู่ในtransaction เดียวกัน

3.2 การต่ออายุ (Renew)

#เงื่อนไขError
1มี loan นี้อยู่LOAN_NOT_FOUND
2ยังไม่ได้คืนLOAN_ALREADY_RETURNED
3ยังไม่เกินกำหนด (date(now) <= date(due_at))LOAN_OVERDUE
4ยังไม่เคยต่ออายุ (renew_count == 0)RENEW_LIMIT_REACHED

ถ้าผ่าน ให้ตั้ง due_at = สิ้นวันของ (date(due_at) + 7 วัน) (นับต่อจาก due เดิม ไม่ใช่จาก now) และ renew_count = 1 ดังนั้นจะต่อวันไหนก็ได้จนถึงวันครบกำหนด ผลจะได้รวม 21 วันเสมอ (ยืมวันที่ 1 ครบกำหนดใหม่วันที่ 22)

3.3 การคืน (Return)

#เงื่อนไขError
1มี loan นี้อยู่LOAN_NOT_FOUND
2ยังไม่ได้คืนLOAN_ALREADY_RETURNED

ถ้าผ่าน ให้ตั้ง returned_at = now เปลี่ยน copy กลับเป็น AVAILABLE แล้วคำนวณค่าปรับ ถ้าค่าปรับมากกว่า 0 ให้สร้าง record ใน FINES ทุกขั้นตอนอยู่ใน transaction เดียวกัน

3.4 สูตรค่าปรับ

lateDays = date(returned_at) - date(due_at)   // นับเป็นวันตามปฏิทิน Asia/Bangkok ไม่สนเวลา
ถ้า lateDays <= 0              → ค่าปรับ 0
fine     = min(lateDays × 10, 500)            // วันละ 10 บาท สูงสุด 500 บาท

Validation

  • name ต้องไม่ว่าง และยาวไม่เกิน 100 ตัวอักษร
  • email ต้องเป็นรูปแบบ email ที่ถูกต้อง และต้องไม่ซ้ำ
  • isbn ต้องเป็นตัวเลข 13 หลัก และต้องไม่ซ้ำ
  • barcode ต้องไม่ว่าง และต้องไม่ซ้ำ
  • page >= 1 และ 1 <= limit <= 100 โดยค่า default คือ 1 และ 20

06ข้อกำหนดสถาปัตยกรรม

โครงสร้างด้านล่างเป็นแค่คำแนะนำ ปรับได้ แต่ต้องแยก layer ให้ชัด

.
├── cmd/api/main.go                 # wiring: สร้าง adapter แล้ว inject เข้า service
├── internal/
│   ├── core/
│   │   ├── domain/                 # entity, value object, domain error, CalculateFine
│   │   ├── port/                   # interface ขาเข้า (services) และขาออก (repos, clock, tx)
│   │   └── service/                # implement use case
│   └── adapter/
│       ├── http/                   # handler, DTO, map error → HTTP status
│       ├── repository/memory/      # in-memory implementation (บังคับ)
│       ├── repository/postgres/    # (bonus)
│       └── clock/                  # SystemClock
└── migrations/                     # (bonus)

กฎที่ห้ามละเมิด

  1. package ใน internal/core/... ห้าม import net/http, database/sql, driver ของ DB หรือ package ใน internal/adapter/...
  2. ห้ามเรียก time.Now() ใน core ให้ใช้ port.Clock แทน
  3. ห้ามสร้าง UUID ตรง ๆ ใน core ให้ใช้ port.IDGenerator แทน
  4. Service ต้องรับ dependency ผ่าน constructor ในรูป interface เช่น NewLoanService(repo port.LoanRepository, …)
  5. Handler ห้ามมี business logic ทำได้แค่ parse, validate รูปแบบ, เรียก service และ map ผลลัพธ์
  6. Domain error ต้องเช็คด้วย errors.Is ได้ และ handler แปลงเป็น HTTP status ในที่เดียว
  7. การยืมและการคืนต้องทำผ่าน TxManager.WithinTx(ctx, fn) โดยตัว in-memory จะ implement ด้วย mutex ก็ได้

ตัวอย่าง outbound port

type Clock interface { Now() time.Time }

type IDGenerator interface { NewID() string }

type TxManager interface {
    WithinTx(ctx context.Context, fn func(ctx context.Context) error) error
}

type LoanRepository interface {
    Create(ctx context.Context, l *domain.Loan) error
    FindByID(ctx context.Context, id string) (*domain.Loan, error)
    Update(ctx context.Context, l *domain.Loan) error
    ListActiveByMember(ctx context.Context, memberID string) ([]domain.Loan, error)
    // ...
}

07ข้อกำหนดเทสต์

ชั้นต้องมีเครื่องมือ
Domaintable-driven test ของ CalculateFine ครบทุกแถวในข้อ 3.4 และ edge case อื่น ๆtesting
Serviceเทสต์ทุก error path ของ Borrow, Renew, Return และ Pay โดยใช้ fake/mock ของ port และ FakeClock ที่กำหนดเวลาเองได้fake เขียนเอง, gomock, mockery
HTTPแต่ละ domain error ต้อง map เป็น status และ code ที่ถูกต้อง และ validation ต้องทำงานnet/http/httptest
Repositoryเทสต์ in-memory repo และ postgres repo ถ้าทำ bonustesting, testcontainers
Concurrencyยิง Borrow copy เดียวกันพร้อมกัน 20 goroutine ต้องสำเร็จแค่ 1 ครั้งgo test -race
เกณฑ์ผ่าน
